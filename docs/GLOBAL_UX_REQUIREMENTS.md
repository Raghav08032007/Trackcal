# Global UI/UX and positive engagement requirements

User instruction for every remaining TrackCal phase, recorded 28 October 2026.

Preserve the existing design and features. Every feature needs a responsive accessible interface, larger readable text, clear navigation and immediate feedback; minimize unnecessary clicks. Use lightweight CSS motion and meaningful, predictable server-owned participation rewards where appropriate. The existing companion should move gently and respond to real actions without covering camera previews, forms or workout controls. Include empty/progress/completion states.

Provide controls for motion, celebration/announcements, companion visibility and notifications. No audio is played by default. Respect OS reduced motion. Avoid random/endless rewards, shame, daily-exercise pressure, calorie restriction/body-change rewards and excessive notifications. Extra volume never yields extra XP.

Each phase must test interactions, navigation, reward idempotency and motion/preferences plus the full previous regression suite. Fix critical failures before declaring completion. Record unsupported physical/device/assistive-technology coverage and all limitations in LIMITATIONS_REGISTER.md. Do not auto-start the next phase.

Phase 3 typography: 18px base on larger screens, 17px mobile; supporting labels approximately 14–15px, 44px minimum button targets, responsive headings. Recheck clipping, contrast and zoom after future edits rather than claiming a global accessibility certification.
